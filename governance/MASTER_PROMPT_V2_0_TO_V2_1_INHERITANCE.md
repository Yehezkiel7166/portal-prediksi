# Master Prompt v2.0 to v2.1 Inheritance

Status: Canonical
Effective date: 2026-07-25

## Rule

Master Prompt v2.1 extends Master Prompt v2.0.

Master Prompt v2.0 remains active except where a requirement is explicitly
marked `SUPERSEDED` by a registered decision.

Absence from v2.1 does not cancel a v2.0 requirement.

## Canonical Documents

1. `MASTER_PROMPT_V2.md`
   - Base AI operating model.
   - Lead Software Architect duty.
   - SEO and architecture governance.
   - Mandatory technical workflow.

2. `docs/governance/MASTER_PROMPT_V2_1.md`
   - Product and architecture extension.
   - Owner and Brand separation.
   - Theme, Homepage, Widget, Slot, RTP, Guide, Complaint, SEO, SERP,
     automation, security, and delivery requirements.

3. `docs/governance/CURRENT_DIRECTION.md`
   - Current delivery priorities and dates.
   - Overrides obsolete delivery windows.

4. `docs/project-brain/CANONICAL_REQUIREMENTS.md`
   - Consolidated active requirements and future direction.

5. `docs/registry/IMPLEMENTATION_STATUS.md`
   - Evidence-based implementation state.

## Explicit Superseded Rules

The following earlier interpretations are superseded:

- Brand 1 active delivery window of 30 days ending 2026-08-23.
- Building Owner Panel before Brand 1 becomes usable.
- Guide as Brand-to-Owner documentation.
- Complaint as Brand-to-Owner support ticket.
- Centralized cross-brand file storage as the mandatory default.
- Date-changing SEO titles for recurring evergreen pages.
- Unknown-domain fallback to Brand 1.
- A single undifferentiated administration panel for Owner and Brand.

## Mandatory Workflow

Every implementation sprint follows:

`INSPECT → SYNC → RED → GREEN → REGRESSION → AUDIT → CTO CROSSCHECK → COMMIT → PUSH → REMOTE VERIFY`

Every sprint must update code, tests, documentation, roadmap, project state,
registries, changelog, manifest, and AI handover where relevant.
